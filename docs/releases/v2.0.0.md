# Color Blind Picker 2.0.0

The new Rust edition replaces the WPF application with a compact Windows color picker built with Rust, Tauri 2 and React. Point at a screen color, read its description, then capture, copy and keep it in your local history.

![Color Blind Picker 2.0.0](https://raw.githubusercontent.com/M3GA17/Color-Blind-Picker/v2.0.0/docs/assets/hero.png)

## Downloads

- **`Color-Blind-Picker_2.0.0_windows-x64-setup.exe`** — Windows x64 installer with Italian/English setup. Downloads WebView2 if missing; an internet connection is required in that case.
- **`Color-Blind-Picker_2.0.0_windows-x64_portable.zip`** — extract the complete archive and launch `color-blind-picker.exe`. Microsoft Edge WebView2 must already be installed. Keep the included source notices with the app.
- **`SHA256SUMS.txt`** — SHA-256 checksums for both packages. On Windows, compare with `Get-FileHash -Algorithm SHA256 <downloaded-file>`.

These packages are built and checked locally, then uploaded manually. No GitHub Actions build or release workflow is used.

The Windows binaries are not code-signed. The portable package runs without installation, but keeps its settings/history in your user profile rather than beside the executable.

## What changed since 1.1.0

- Complete rewrite from C# / WPF to **Rust + Tauri 2 + React / TypeScript**.
- Compact **Graphite** interface, tighter margins, red close control and the original color-wheel/eyedropper logo.
- Live Windows screen sampling, including virtual-desktop coordinates for multiple monitors.
- Transparent capture overlay with a pointer tooltip, click to save/copy, and **Esc** to cancel.
- **HEX or RGB** copying, always-on-top mode, and persistent Italian/English preferences.
- Local history for up to **1,000 colors**, per-entry copying, deletion and undo.
- New descriptions based on the historical **ISCC–NBS nomenclature**, matched in CIELAB with **CIEDE2000**. Near-neutral colors stay neutral, and a brief label debounce reduces flicker while exact values continue updating immediately.
- Documented reference data, translations, conversion choices, tests and refreshed screenshots.

## Color-name limitations

Naming is an **ISCC–NBS-based nearest-centroid approximation**, not exact reconstruction of the original naming regions. There are 267 source categories and **266 usable numerical references**; one ambiguous printed notation is excluded. Italian terms are project translations. Names can differ from CSS keywords and everyday usage. RGB/HEX values are preserved independently of the description.

Screen RGB is interpreted as **SDR sRGB** for naming. HDR and monitor-profile compensation are outside this release. See the [naming guide](https://github.com/M3GA17/Color-Blind-Picker/blob/v2.0.0/docs/COLOR-NAMING.md) for the source, exclusions and method.

## Coming from WPF

Before the first launch, put the old `colorList.txt` beside the new executable or in its working directory. The app imports the JSON color list and preserves the original file. Existing Rust-format history takes precedence.

Settings and history are stored locally in `%APPDATA%\io.github.m3ga17.colorblindpicker\state.json`. Existing Rust history retains its exact values; names are recalculated with the new classifier.

## Validation

The release is checked with the frontend build and nine browser/interface tests, ten Rust tests (including all 34 independent CIEDE2000 reference pairs), formatting and Clippy, plus a native Windows smoke test of actual screen sampling, clipboard, capture, history and settings. The Windows installer and portable archive are built locally; their hashes are supplied with the release.

The previous WPF build remains available as [v1.1.0](https://github.com/M3GA17/Color-Blind-Picker/releases/tag/v1.1.0).
